## 1. Назначение документа

Этот документ описывает фактически реализованный функционал GZWhisper. Его можно целиком передать в ChatGPT Pro или другому исследовательскому агенту как исходный контекст для:

- поиска прямых и косвенных конкурентов;
- сравнения функционала, UX, приватности, платформ, бизнес-моделей и позиционирования;
- выявления функций, которых сейчас нет в GZWhisper, но которые стоит рассмотреть;
- отделения действительно новых возможностей от уже реализованных;
- приоритизации идей с учётом локальной архитектуры и ориентации на macOS.

Описание построено по текущим исходникам, README, документации сборки и истории изменений. Это не маркетинговый список обещаний: там, где платформы отличаются или функция имеет ограничение, это указано прямо.

## 2. Краткое описание продукта

GZWhisper — локальное настольное приложение для транскрибации аудио и видео. После загрузки модели распознавание выполняется на компьютере пользователя. Основная и наиболее развитая версия — нативное приложение для macOS на SwiftUI. Также существуют упрощённые варианты для Linux и Windows, построенные на Python/Tkinter; Windows-вариант распространяется как portable-приложение.

Основные продуктовые сценарии:

1. Добавить один или несколько существующих аудио- или видеофайлов и последовательно транскрибировать их локально.
2. Записать системный звук, микрофон или оба источника одновременно на Mac, сохранить запись и поставить её в очередь на транскрибацию.
3. Управлять очередью длительных заданий: выбирать отдельные элементы, менять порядок, пропускать текущий файл, ставить очередь на паузу после текущего задания, продолжать или отменять обработку.
4. Работать с локальной историей записей и транскриптов: искать, переименовывать, открывать, повторно ставить в очередь, находить файлы в Finder и удалять с возможностью отмены.
5. Просматривать и редактировать распознанный текст, копировать его и экспортировать в TXT или JSON.

Ключевая продуктовая идея — дать пользователю самостоятельный локальный инструмент без обязательного аккаунта, облачной отправки медиа и подписки на минуты транскрибации.

## 3. Платформы и статус поддержки

### 3.1. macOS — основной продукт

- Нативный интерфейс SwiftUI.
- Поддерживаются Apple Silicon Mac (`arm64`).
- Минимальная версия ОС для приложения: macOS 12.
- Запись системного звука требует macOS 13 или новее, так как используется ScreenCaptureKit.
- Это единственная стабильная и полноценно протестированная версия.
- Текущий bundle id: `com.gzakharov.gzwhisper`.
- Приложение собирается как `GZWhisper.app` и распространяется в ZIP или DMG.

### 3.2. Linux — дополнительная версия

- Интерфейс Python/Tkinter.
- Реализован основной сценарий «медиафайл → очередь → локальная транскрибация → история → экспорт».
- Для извлечения звука из видео требуется установленный `ffmpeg`.
- Доступны install/uninstall-скрипты и сборка архива.
- Функциональность заметно уже, чем в версии для macOS.

### 3.3. Windows — portable-версия в разработке

- Использует тот же Python/Tkinter-код, что и Linux-версия.
- Запускается из распакованной папки без установщика и без системного Python.
- Для видео нужен `ffmpeg.exe` рядом с приложением либо в `PATH`.
- Модели, транскрипты и история хранятся в профиле пользователя и не привязаны к папке portable-приложения.
- Версия частично работоспособна, но официально ещё требует исправлений и полноценного тестирования.

## 4. Локальная модель и механизм распознавания

### 4.1. Используемый стек

- Движок распознавания: `faster-whisper`.
- Инференс выполняется через CTranslate2.
- Устройство выбирается автоматически (`device="auto"`).
- Тип вычислений зафиксирован как `int8`.
- При транскрибации используется `beam_size=5`.
- VAD-фильтрация включена (`vad_filter=True`) для отсечения участков без речи.
- Распознавание выполняется локально с `local_files_only=True` после подготовки модели.
- Отдельных пользовательских настроек beam size, VAD, compute type, устройства или температуры в интерфейсе нет.

### 4.2. Модели по умолчанию

При скачивании приложение последовательно пробует два репозитория Hugging Face:

1. `mobiuslabsgmbh/faster-whisper-large-v3-turbo` — основной кандидат.
2. `SYSTRAN/faster-whisper-large-v3` — резервный кандидат, если первый источник не удалось скачать или инициализировать.

Пользователь не выбирает модель из каталога внутри приложения: текущий поток скачивания использует заданную цепочку кандидатов. При этом можно подключить уже существующую локальную папку с совместимой моделью faster-whisper.

### 4.3. Управление моделью

Пользователь может:

- выбрать папку назначения и скачать модель;
- видеть источник скачивания;
- видеть объём загруженных данных и общий размер, если он известен;
- видеть процент загрузки при известном общем размере либо неопределённый прогресс;
- продолжить прерванную загрузку средствами Hugging Face snapshot download;
- подключить существующую локальную модель;
- автоматически провалидировать выбранную папку пробной загрузкой модели;
- открыть папку модели в Finder или файловом менеджере;
- перейти на страницу модели в Hugging Face из macOS-интерфейса;
- удалить скачанную через приложение модель;
- отвязать подключённую внешнюю модель без удаления самой внешней папки.

Приложение хранит ссылку на выбранную модель и восстанавливает её между запусками. Если папка исчезла, модель считается недоступной.

### 4.4. Локальное Python-окружение на macOS

- В релизную сборку включается Python 3.12 для Apple Silicon.
- Приложение создаёт собственное виртуальное окружение в Application Support.
- Зависимости могут устанавливаться из встроенного offline wheelhouse без сети.
- Если offline-установка не удалась, предусмотрена попытка установки через PyPI с раздельной диагностикой ошибок.
- Устаревшее или привязанное к другому Python виртуальное окружение пересоздаётся автоматически.
- Запуск Python-процессов запрещает создание `__pycache__` внутри подписанного bundle, чтобы не повредить подпись ресурсов.
- Если runtime отсутствует или повреждён, macOS-интерфейс показывает заметное сообщение о проблеме и блокирует зависящие от него операции.

## 5. Добавление и подготовка медиа

### 5.1. Добавление файлов на macOS

Поддерживаются два способа:

- системный диалог выбора файлов;
- drag-and-drop файлов на окно приложения с визуальной подсветкой зоны приёма.

Можно выбрать несколько файлов одновременно. Приложение принимает типы, которые macOS распознаёт как audio или movie через Uniform Type Identifiers. Файлы без поддерживаемого медиа-типа отбрасываются.

Во время активной записи добавление файлов блокируется, чтобы не смешивать состояние capture-сессии с импортом.

### 5.2. Добавление файлов на Linux и Windows

Поддерживается множественный выбор через системный диалог. Явный список расширений:

- аудио: MP3, WAV, M4A, AAC, FLAC, OGG, OPUS;
- видео: MP4, MKV, MOV, AVI, WEBM, M4V.

Drag-and-drop в Tkinter-версии не реализован.

### 5.3. Извлечение аудио из видео

На macOS аудиодорожка автоматически извлекается во временный M4A средствами AVFoundation. Если в видео нет аудиодорожки, пользователь получает отдельную понятную ошибку. Временный файл удаляется после завершения или ошибки транскрибации.

На Linux/Windows звук извлекается во временный M4A через `ffmpeg`. При отсутствии `ffmpeg` выводится явная ошибка; аудиофайлы при этом могут обрабатываться без него.

### 5.4. Предупреждение о тяжёлых файлах

macOS-версия помечает импорт как потенциально тяжёлый, если хотя бы один файл:

- длится 60 минут или больше; либо
- имеет размер 2 ГБ или больше.

Это предупреждение, а не запрет: файл остаётся в очереди.

## 6. Язык интерфейса и язык распознавания

### 6.1. Локализация интерфейса

Интерфейс автоматически выбирается по системной локали:

- русский;
- английский;
- китайский.

Для всех других локалей используется английский. Ручного переключателя языка интерфейса нет.

### 6.2. Язык транскрибации

В интерфейсе доступны четыре режима:

- Auto — автоматическое определение языка моделью;
- русский (`ru`);
- английский (`en`);
- китайский (`zh`).

После обработки показывается определённый язык. Сам Whisper способен работать с большим числом языков, но текущий пользовательский список для принудительного выбора ограничен этими тремя языками плюс Auto.

## 7. Очередь транскрибации на macOS

### 7.1. Создание очереди

Каждый добавленный медиафайл становится отдельным элементом со статусом `queued`. Запись, созданная внутри приложения, после сохранения также автоматически добавляется в историю и очередь.

Очередь отображает количество ожидающих элементов. Активные элементы сортируются по порядку очереди и располагаются выше завершённой истории.

### 7.2. Запуск всей очереди или выбранных элементов

Можно:

- запустить все ожидающие файлы;
- отметить один или несколько доступных элементов флажками и запустить только их;
- запустить выбранный элемент истории;
- запустить конкретный queued-элемент кнопкой в его строке;
- поставить доступный элемент истории обратно в очередь, если у него нет готового транскрипта и исходный файл существует.

Транскрибация выполняется последовательно, по одному файлу. Параллельной обработки нескольких файлов нет.

### 7.3. Управление выполняющейся очередью

Доступны следующие действия:

- **Cancel queue** — завершить активный процесс и отменить текущий проход; текущий элемент возвращается в queued-состояние.
- **Pause after current** — дать текущему файлу закончиться и затем остановить очередь без потери оставшихся заданий.
- **Keep going** — отменить запрос паузы после текущего файла.
- **Resume queue** — продолжить ранее поставленную на паузу очередь.
- **Skip current** — остановить текущую обработку, вернуть файл в очередь и переместить его в конец, затем перейти к следующему.
- **Clear queue** — убрать все ожидающие задания. Временные импортированные элементы без артефактов удаляются из списка; сохранённые элементы переводятся в нейтральное состояние.
- **Remove from queue** — убрать один ожидающий элемент.
- **Move earlier / Move later** — изменить позицию отдельного queued-элемента.

Удаление элемента во время его активной обработки заблокировано.

### 7.4. Прогресс и ETA

Worker отправляет события с обработанной и общей длительностью. Интерфейс показывает:

- процент текущего файла;
- имя текущего файла;
- оценку оставшегося времени после накопления минимально достаточного прогресса;
- spinner и статус `processing` в истории;
- состояние каждого элемента: ready, queued, processing, completed или failed;
- позицию активного/ожидающего элемента в очереди;
- текст ошибки непосредственно у failed-элемента.

Оценка ETA рассчитывается линейно по уже прошедшему времени и текущей доле выполнения.

### 7.5. Одновременная запись и транскрибация

Начиная с v1.5.2 пользователь может начать новую аудиозапись, пока очередь транскрибации уже выполняется. В нижней строке состояния одновременно показываются отдельные сводки по транскрибации и записи.

Ограничение асимметрично: запуск новой очереди во время уже идущей записи блокируется. Сохранённая запись попадает в очередь и может быть обработана после остановки записи.

## 8. Запись аудио на macOS

### 8.1. Режимы записи

Доступны три режима:

1. **System + microphone** — одновременная запись системного звука и микрофона.
2. **System only** — только системный звук.
3. **Microphone only** — только микрофон.

Микрофон записывается через AVFoundation, системное аудио — через ScreenCaptureKit. Для соответствующих режимов macOS запрашивает разрешения Microphone и Screen & System Audio Recording.

### 8.2. Управление записью

Пользователь может:

- начать запись;
- поставить её на паузу;
- продолжить;
- остановить;
- видеть чистое время записи без учёта пауз;
- выбрать режим до начала записи;
- скрыть и снова показать плавающее мини-окно;
- включить или выключить автоматический показ мини-окна при старте следующей записи.

Паузы не превращаются в длинные участки тишины: временные метки последующих аудиосэмплов сдвигаются на суммарную длительность паузы.

### 8.3. Формат записи

- Контейнер: M4A.
- Кодек: AAC.
- Частота дискретизации: 44,1 кГц.
- Системный звук: стерео, 96 кбит/с.
- Микрофон: моно, 64 кбит/с.
- В комбинированном режиме дорожки сводятся в итоговый M4A с единичной громкостью каждой дорожки.

Если объединить две дорожки не удалось, приложение сохраняет пригодную одиночную дорожку вместо полной потери записи.

### 8.4. Имена и размещение записей

Записи сохраняются в папке транскриптов с именами вида:

- `recording-system-mic-<timestamp>.m4a`;
- `recording-system-<timestamp>.m4a`;
- `recording-mic-<timestamp>.m4a`.

Сразу после сохранения запись появляется в истории с метаданными режима и автоматически получает queued-статус.

### 8.5. Плавающее recording HUD

Во время записи может показываться компактная панель размером 238×90 px:

- всегда поверх обычных окон;
- доступна на всех Spaces и поверх полноэкранных приложений;
- не активирует основное приложение;
- перемещается перетаскиванием за фон;
- по умолчанию размещается в правом верхнем углу активного экрана;
- показывает красный индикатор, таймер, Pause/Resume и Stop;
- может быть закрыта без остановки записи и повторно открыта из главного окна.

### 8.6. Защита и восстановление прерванных записей

Приложение хранит описание активной recording-сессии и пишет отдельные staging-файлы системной и микрофонной дорожек. M4A создаются фрагментированными с интервалом фрагмента около пяти секунд, что повышает шанс восстановления после аварийного завершения.

Автоматическая финализация запускается:

- перед переходом Mac в сон;
- после пробуждения как резервный сценарий;
- при неожиданной остановке ScreenCaptureKit;
- при runtime error или interruption микрофонной capture-сессии.

При следующем запуске приложение также проверяет незавершённую сессию. Для восстановления принимаются только файлы больше 1 КБ с читаемой аудиодорожкой. Если две дорожки нельзя объединить, сохраняется выжившая дорожка; для комбинированного режима предпочтение отдаётся микрофонной. После завершения или ошибки состояние UI сбрасывается, чтобы пользователь мог начать новую запись.

Запись системного звука, плавающий HUD и автоматическое восстановление отсутствуют в текущих Linux/Windows-вариантах.

## 9. История на macOS

### 9.1. Содержимое элемента истории

Элемент может содержать:

- исходное имя и путь медиафайла;
- пользовательское отображаемое имя;
- дату создания или завершения;
- длительность;
- путь к записи, если звук создан приложением;
- путь к TXT-транскрипту;
- определённый язык;
- идентификатор модели;
- режим записи;
- состояние задания;
- порядок очереди;
- текст ошибки.

Прогресс и ETA являются runtime-полями и не сохраняются между запусками.

### 9.2. Типовые бейджи

В строках истории используются компактные бейджи:

- `t` — есть транскрипт;
- `a` — есть сохранённая аудиозапись;
- `t+a` — есть и транскрипт, и аудио.

Tooltip объясняет значение каждого бейджа.

### 9.3. Поиск

Поиск разворачивается внутри боковой панели с анимацией и показывает число найденных элементов относительно общего количества.

Поиск охватывает:

- отображаемое и оригинальное имя;
- путь к исходному файлу;
- путь к аудио;
- путь к транскрипту;
- полный текст сохранённого транскрипта.

Сопоставление нечувствительно к регистру, диакритике и вариантам ширины символов. Запрос нормализует пробелы. Ввод имеет debounce 180 мс. Чтение транскриптов, проверка дат изменения и полнотекстовое сопоставление выполняются вне main actor через кэширующий actor-backed индекс. Кэш пересобирается для конкретного элемента, если изменился источник метаданных или дата модификации transcript-файла.

### 9.4. Переименование

- Переименование выполняется inline прямо в строке истории.
- Можно подтвердить Enter/галочкой или отменить.
- Пустое имя либо имя, совпадающее с исходным, сбрасывает кастомное название.
- Переименование меняет только отображаемое имя записи в истории; исходный аудио-, видео- или TXT-файл на диске не переименовывается.
- При экспорте открытого элемента предложенное имя TXT/JSON формируется из текущего отображаемого имени. Для непереименованного элемента исходное расширение медиа удаляется, а недопустимые символы имени файла заменяются.
- В отдельном режиме массового экспорта можно отметить несколько завершённых элементов, в том числе выбрать все видимые результаты поиска, и сохранить их одним ZIP-архивом с отдельным TXT- или JSON-файлом на каждый транскрипт. Совпадающие имена автоматически получают числовые суффиксы.

### 9.5. Действия со строкой истории

В зависимости от состояния и имеющихся артефактов пользователь может:

- открыть завершённый транскрипт в редакторе;
- поставить подходящий элемент в очередь;
- запустить queued-элемент немедленно;
- выбрать несколько элементов для запуска;
- менять позицию queued-элемента;
- убрать его из очереди;
- показать TXT в Finder;
- показать записанное аудио в Finder;
- переименовать элемент;
- удалить элемент.

Кнопки быстрых действий появляются при наведении, чтобы история оставалась компактной.

### 9.6. Удаление и Undo

При удалении на macOS:

- элемент сразу исчезает из списка;
- в footer появляется единый контрол с именем удалённого элемента и кнопкой Undo;
- Undo доступен 15 секунд;
- до истечения окна файлы физически остаются на месте;
- после истечения срока TXT и связанная запись перемещаются в macOS Trash, а не удаляются безвозвратно;
- импортированный исходный аудио- или видеофайл не удаляется, поскольку он не считается созданной приложением записью;
- удаление нового элемента во время активного Undo немедленно завершает удаление предыдущего.

Linux/Windows-версия удаляет transcript-файл сразу и не имеет Undo/Trash-поведения. Исходное импортированное медиа там также не удаляется.

## 10. Просмотр, редактирование и экспорт результата

### 10.1. Редактор

Завершённый транскрипт открывается во встроенном прокручиваемом текстовом редакторе с моноширинным шрифтом. Текст можно вручную редактировать, выделять и копировать. Кнопка Copy all помещает весь текущий текст в системный буфер обмена.

Важно: ручные правки в редакторе не перезаписывают автоматически сохранённый исторический TXT. Их можно сохранить через экспорт. При повторном открытии элемента из истории будет заново прочитан исходный transcript-файл.

### 10.2. Автоматически создаваемый TXT

После успешной транскрибации приложение автоматически сохраняет plain-text-файл в локальной папке транскриптов. Имя строится из безопасной версии basename исходного файла и Unix timestamp. Текст состоит из распознанных сегментов, по одному сегменту на строку, без временных меток.

### 10.3. Ручной экспорт TXT

- Экспортирует текущее содержимое редактора в UTF-8 plain text.
- Пользователь выбирает место сохранения.
- На macOS диалог предлагает имя на основе текущего имени элемента истории.
- На Linux/Windows пока предлагается общее имя `transcript.txt`.

### 10.4. Ручной экспорт JSON

JSON может включать:

- `generated_at`;
- `text` — текущее содержимое редактора;
- `detected_language`;
- `segments` — массив объектов `start`, `end`, `text`;
- `source_file`, если известен;
- `model_id`, если известен;
- `model_path`, если подключена модель.

Ограничение: сегменты с таймкодами хранятся только в памяти текущего сеанса распознавания и не сохраняются в истории. Поэтому JSON, экспортированный сразу после транскрибации, содержит сегменты, а после повторного открытия старого элемента из истории массив `segments` будет пустым. В интерфейсе также нет визуального посегментного/timeline-редактора.

На macOS имя JSON предлагается по текущему имени элемента истории; на Linux/Windows используется `transcript.json`.

### 10.5. Массовый экспорт на macOS

- Запускается кнопкой архива в заголовке истории и использует отдельный от очереди режим выбора.
- Экспортирует только завершённые элементы, у которых сохранён transcript-файл.
- Пользователь выбирает единый формат для всей выборки: TXT или JSON.
- Результат — один ZIP без дополнительной корневой папки, с отдельным файлом на каждый выбранный транскрипт.
- Имена строятся из текущих отображаемых имён, очищаются от недопустимых символов и делаются уникальными числовыми суффиксами.
- Исторические JSON содержат текст, дату экспорта, исходный путь, язык и модель при наличии; `segments` остаётся пустым, поскольку сегменты не сохраняются в истории.

## 11. Интерфейс и UX macOS

### 11.1. Основная компоновка

Окно состоит из:

- компактной верхней карточки со словом GZWhisper, версией, статусом модели и прогрессом загрузки;
- скрываемой левой панели истории;
- карточки входа с очередью, языком и записью;
- большой карточки редактора результата;
- нижней строки состояния и debug-меню.

Минимальный размер окна: 640×500; идеальный — около 1100×760. Для узких окон используются альтернативные компактные варианты контролов: текстовые кнопки заменяются иконками, а блок записи перестраивается на две строки. Это позволяет избежать вертикального текста и обрезанных кнопок.

### 11.2. Визуальный стиль

- Поддерживаются светлая и тёмная системные темы.
- Используются полупрозрачные карточки, мягкий градиент фона, rounded controls и системные SF Symbols.
- Текущий выбранный элемент истории визуально выделяется.
- Состояния имеют цветовые индикаторы: completed — зелёный, processing — оранжевый, failed — красный.
- Hover-состояние локализовано внутри отдельной строки, чтобы движение указателя не вызывало перерисовку всей истории.

### 11.3. Строка состояния

В обычном состоянии footer показывает последнее сообщение. Во время работы:

- транскрибация показывает имя и процент;
- запись показывает таймер и состояние паузы;
- при одновременной работе обе сводки разделены divider;
- уведомление об удалении и Undo показывается отдельно, без дублирования текста статуса.

### 11.4. Диагностика

Debug-меню позволяет:

- скопировать диагностический отчёт в буфер обмена;
- открыть runtime-папку в Finder;
- перейти на GitHub проекта;
- открыть сайт автора.

Отчёт включает версию и build, язык UI, текущий статус, runtime issue, выбранный и определённый язык, размеры истории и очереди, состояния записи/транскрибации, выбранный history item, первую найденную ошибку и пути/состояние Python runtime и venv.

## 12. Локальное хранение, приватность и жизненный цикл данных

### 12.1. Что остаётся локальным

- Распознавание выполняется локально.
- Медиа для транскрибации не отправляется в облачный сервис GZWhisper.
- Аккаунт и авторизация не требуются.
- В проекте нет встроенной телеметрии, аналитики использования, рекламного SDK или синхронизации истории.
- После загрузки модели транскрибация может работать без сети, если runtime и зависимости уже подготовлены.

Сеть требуется для первичного скачивания модели и, при отсутствии/ошибке встроенного набора зависимостей, может понадобиться для установки Python-пакетов через PyPI.

### 12.2. Где хранятся данные на macOS

- Модель и транскрипты по умолчанию: `~/Documents/GZWhisper/`.
- Транскрипты, записи и history JSON: `~/Documents/GZWhisper/transcripts/`.
- Runtime, venv, worker и ссылка на выбранную модель: `~/Library/Application Support/GZWhisper/`.
- Staging незавершённых записей: `~/Library/Application Support/GZWhisper/recording-sessions/in-progress/`.

Пользователь может выбрать другую папку при скачивании модели, но папка транскриптов по текущей реализации остаётся внутри стандартного `~/Documents/GZWhisper`.

### 12.3. Сохранение истории

История хранится как локальный JSON. Между запусками сохраняются завершённые, failed и имеющие артефакты элементы, а также queued-записи. Чисто временные импортированные элементы без результата не обязаны сохраняться. Если приложение завершилось во время обработки сохранённой аудиозаписи, при следующем запуске такой элемент возвращается в очередь; неподкреплённый аудиоартефактом processing-элемент помечается failed.

## 15. Сильные стороны, которые важно не потерять при заимствовании идей

При оценке функций конкурентов следует считать базовыми принципами GZWhisper:

- **Local-first:** основной контент пользователя остаётся на его компьютере.
- **Отсутствие обязательного аккаунта:** быстрый старт и независимость от облачного сервиса.
- **Предсказуемое владение файлами:** обычные TXT, JSON и M4A доступны вне приложения.
- **Надёжность длительной записи:** staging, фрагментированные файлы, sleep/wake handling и single-track fallback.
- **Управляемая очередь:** пользователь контролирует порядок и может паузить, пропускать и отменять задания.
- **Прозрачная модель:** видны её источник и папка; можно подключить свою локальную модель.
- **Работа без тарификации по минутам:** после скачивания модели нет серверного счётчика обработки.
- **macOS-native UX:** Finder, Trash/Undo, системные разрешения, light/dark mode, Spaces и компактный HUD.
- **Сохранность импортированных оригиналов:** удаление записи истории не удаляет исходное внешнее медиа.

Заимствуемые функции желательно оценивать на совместимость с этими принципами. Облачная функция может быть рассмотрена как опциональная, но не должна незаметно разрушать локальный сценарий.

## 17. Короткая формулировка продукта для начала исследования

GZWhisper — local-first desktop-приложение, в первую очередь для Apple Silicon Mac, которое локально транскрибирует аудио и видео через faster-whisper, умеет скачивать или подключать локальную модель, записывать системный звук и микрофон в трёх режимах, восстанавливать прерванные записи, управлять последовательной очередью, вести полнотекстово ищущую локальную историю и экспортировать результат в TXT/JSON. Продукт не требует аккаунта и не отправляет пользовательское медиа в собственное облако; Linux и Windows portable пока предоставляют более узкий core-сценарий без записи и развитого управления библиотекой.
